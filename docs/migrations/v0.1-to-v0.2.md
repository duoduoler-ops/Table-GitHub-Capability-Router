# Migrate from v0.1.0 to v0.2.0

v0.1.0 was a prompt-triggered Markdown starter kit. v0.2.0 adds the first deterministic machine schema, generated views, semantic project references, transactions, and repository validation.

## Recommended path

1. Keep the v0.1.0 vault as a backup.
2. Initialize a new isolated v0.2.0 workflow root with `scripts/workflow.py init`.
3. Recreate or import canonical project and capability records. Do not copy generated indexes or routers.
4. Promote only approved S/A/B projects to `retained` or `reference`.
5. During promotion, provide at least two ordinary-language semantic examples, one trigger level, and negative routing.
6. Run `rebuild`, then `validate`.

New candidate, evaluated, rejected, archived, C, and D project records use:

```yaml
semantic_examples: none
trigger_level: explicit_only
negative_routing: none
```

Eligible `retained/reference` records use a flat, deterministic separator:

```yaml
semantic_examples: First ordinary phrase || Second ordinary phrase
trigger_level: gated
negative_routing: Do not route when the ordinary no-extra-project answer is enough
```

Do not hand-create `indexes/project-semantic-routing.md`. It is generated from canonical project records. A semantic match is a read-only reference and never grants clone, installation, login, unknown script execution, configuration changes, or publishing.

## 中文

v0.1.0 是提示词触发的 Markdown 模板；v0.2.0 首次加入确定性机器 Schema、派生表、项目语义命中、事务写回和仓库校验。

建议保留旧目录作为备份，在新隔离目录初始化 v0.2.0，只迁移项目卡和能力记录等事实源，不复制旧索引和路由。只有经批准的 S/A/B `retained/reference` 项目填写两条以上日常说法、命中级别和禁止命中条件。最后运行 `rebuild` 和 `validate`。

`indexes/project-semantic-routing.md` 必须由脚本生成，不能手工维护。语义命中只提供只读参考，不授权执行任何外部动作。
